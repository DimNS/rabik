## Context

См. `proposal.md` (Why). Текущее состояние: `pickVariant(x, y, tileSeed, count)` в `src/view/renderer.ts` — независимый хэш на клетку, `drawCell` рисует тайл встык без учёта соседей. У recipes в `scripts/gen-tile-variants.ts` узор обрезается краем тайла (кирпич: `BW=32/BH=16` не делят 130; камень — ворона/diagram без периодичности), поэтому стыки рвутся дважды: и сменой варианта, и обрезкой узора. Soil/road трогать не надо — проблема только в `wall`. См. спеки: `wall-coherence` (ADDED), `tile-variants` + `game-rendering` (MODIFIED).

## Goals / Non-Goals

**Goals:**
- Соседние `wall` выглядят пятнами 2×2+, одиночной ряби нет; внутренние стыки без тёмных швов, внешние кромки завершены.
- Чистая функция от `(x, y, seed)` + локальная маска соседей; `redrawTile` остаётся O(1) без прохода по всей карте.

**Non-Goals:**
- Полный автотайлинг на 16/47 тайлов и новые арты — не делаем.
- Soil/road, логика, формат уровней — без изменений.

## Decisions

### 1. Кластеры через квантованный хэш блока 2×2

`pickVariant` для `soil`/`road` не меняется. Для `wall` — новая чистая функция `pickWallVariant(x, y, seed, count) = hash(bx, by, seed)`, где `bx = floor(x/2)`, `by = floor(y/2)` (тот же `imul`-хэш, что сейчас). Все 4 клетки блока делят вариант.

Почему так, а не копирование варианта соседа с порогом: сосед-копирование требует доступа к сетке, порядка обхода и кэша (иначе `redrawTile` одной клетки даст другой результат, чем `renderAll`), квантование — stateless, детерминировано по определению и проходит сценарий «4 подряд — хотя бы одна пара совпадает» конструктивно: любое окно из 4 клеток покрывает не более 2 блоков.

Альтернатива «блок 3×3 / шум с порогом» отвергнута: 3×3 на карте 7×7 даёт 2–3 пятна на всю карту (монотонно), шум с порогом снова вводит одиночки.

`ponytail: блок фиксирован 2×2, вынести в константу WALL_BLOCK=2 если карты станут больше.`

### 2. Стыки — процедурная кромка по маске соседей, без новых ассетов

`drawCell` для `wall` вычисляет 4-битную маску соседей-`wall` (нужен доступ к `state.grid` — сигнатура `drawCell` расширяется, `pickVariant` остаётся чистой). Внутренние границы (сосед тоже `wall`) рисуются без затемнения — шов исчезает; внешние границы (сосед `soil`/`road`/край карты) получают тёмную кромку 6–8 px поверх базового тайла (fillRect с альфой, `imageSmoothingEnabled=false` уже есть).

Почему не новые переходные тайлы: это 16+ новых артов, генератор, атлас и галерея — на порядок больше диффа ради того же визуального эффекта «массив с оконтуренным краем». Кромка поверх существующего тайла даёт 90% эффекта десятком строк.

### 3. Рецепты генератора — только делители 130, без рефакторинга шума

Если после п.1–2 швы узора внутри блока всё ещё видны: `BW/BH` кирпича и периоды `makeNoise` выбирать только из делителей 130 (26/65) — узор станет периодическим и сошьётся сам. Полную тайлируемость ворона (stone) не делаем: камень и так разбит на пятна 2×2, обрезка видна редко.

## Risks / Trade-offs

- [Risk] Пары 2×2 выглядят «кирпичной кладкой» на длинных стенах → Mitigation: приемлемо по спеку (требуются именно пятна 1–2 вариантов); если надоест — чередовать ориентацию блока от `seed`.
- [Risk] Кромка поверх тайла спорит с художественным краем рецепта → Mitigation: кромка рисуется только на внешней границе массива, внутри — чистое изображение.
- [Risk] Та же карта выглядит иначе, чем раньше → Mitigation: ожидаемо и зафиксировано в proposal (логика и формат не меняются, только картинка).

## Migration Plan

Миграции нет: изменение чисто визуальное, формат уровней и атласа не меняется. Откат — вернуть `drawCell` на `pickVariant` для всех типов.
