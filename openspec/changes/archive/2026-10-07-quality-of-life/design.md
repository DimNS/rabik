## Context

См. `proposal.md` (Why). Точки внедрения: `computeLayout` в `src/view/layout.ts` — единственное место расчёта `tileSize`; `createRenderer().render` в `src/view/renderer.ts` — единственное место отрисовки кролика; `tryMove` в `src/core/game-rules.ts` + цикл в `src/index.ts` (там уже живёт лог победы `Уровень решён` с флагом `announced`). Направление взгляда — чисто view-состояние, в `GameState` его нет; флаг тупика в `GameState` пока отсутствует.

## Goals / Non-Goals

**Goals:**
- Cap тайла 130px с сохранением центрирования и резкости на больших экранах.
- Поворот кролика по направлению шага без новых ассетов и без сброса фазы анимации.
- Детект тупика после шага с однократным логом по аналогии с победой.
- README для входа в проект.

**Non-Goals:**
- Новые спрайты/направленные кадры кролика, изменение генератора атласа.
- Экран проигрыша, рестарт уровня, счёт ходов — только лог как у победы.
- Ребаланс уровней и изменение правил проходимости.

## Decisions

- **Cap 130 в `computeLayout`: `Math.min(130, Math.floor(...))`.** Одна строка в единственной точке расчёта, покрывается существующим `layout.test.ts`. Альтернатива — даунскейл в renderer/CSS — отвергнута: больше кода и второй источник истины для размера.
- **Поворот через `ctx.save / translate / rotate` в `renderer.render`, направление хранится в замыкании `index.ts` (дефолт `'up'`), обновляется только при `tryMove === true`.** Не требует новых кадров `rabbit_*`, фаза анимации из `sprite-anim.ts` не трогается. Альтернатива — 4 набора спрайтов / поле в `GameState` — отвергнута: тянет генератор атласа и пачкает ядро view-состоянием.
- **Тупик как чистая функция `isStuck(state)` в `game-rules.ts` + флаг `stuck` в `GameState` (дефолт `false`, выставляется в `tryMove` после хода при `soilCount > 0`), лог в цикле `index.ts` с отдельным флагом `announcedGameOver` по образцу `announced`.** Логика unit-тестируема без DOM, приоритет победы: сначала проверка `solved`, потом тупика. Альтернатива — проверка только в цикле без флага — отвергнута: состояние нельзя assert-ить в `game.test.ts`.
- **README — один файл в корне: запуск (`bun`/`make`), структура `src/`, уровни/спрайты, правила (win/game over), управление.** Без влияния на рантайм; пишется по факту кода, а не по памяти.

## Risks / Trade-offs

- [Поворот pixel-art через canvas может дать полупиксельное мыло] → Mitigation: `imageSmoothingEnabled = false` уже включён, повороты только на 90°, центр — середина тайла.
- [Поля по краям на сверхшироких экранах после cap 130] → Mitigation: принимается; `offsetX/offsetY` уже центрируют поле, поведение предсказуемо.
- [Флаг `stuck` может пережить рестарт уровня] → Mitigation: сброс в `createGameState`/`createEmptyState` вместе с `solved`.
- [Двойной лог win + game over на последнем ходе] → Mitigation: порядок проверок — `solved` первым, тупик только при `!solved`.

## Migration Plan

Миграция не нужна. Изменение обратно совместимо: cap меняет только визуал на больших экранах, флаг `stuck` аддитивен, README не затрагивает код. Откат — revert коммита.
