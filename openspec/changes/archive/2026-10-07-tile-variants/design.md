## Context

См. `proposal.md` (Why). Текущее состояние: `scripts/gen-atlas.ts` требует ровно 3 JPG 130×130, клеит `tiles.jpg` (после `tiles-jpg`; до него был `tiles.png`) с кадрами `wall/soil/road`; `src/view/renderer.ts:drawCell` маппит тип клетки 1:1 на кадр; `LevelData` не имеет seed. Ограничения: 0 runtime-зависимостей, оффлайн, проверки `make ai-check`, `core/` не трогаем (вариант — чисто визуальный слой).

## Goals / Non-Goals

- Goals: папки вариантов в `raw/`; мульти-атлас с алиасами; процедурный генератор 6 рецептов; оффлайн-галерея в `tools/`; seeded-выбор варианта; `tileSeed` с дефолтом от `id`.
- Non-Goals: per-cell override в JSON уровня; автотайлинг стыков (переходы дорога-земля и т.п.); AI-генерация картинок; изменение `game-rules`/`game-state`.

## Decisions

1. **Раскладка мульти-атласа — 3 ряда, ширина по максимуму.** Ряд 0 — wall-варианты, ряд 1 — soil, ряд 2 — road; ширина JPG = `maxCount × 130`. Альтернатива — один длинный ряд — отвергнута: ряды сохраняют детерминированные координаты и читаемость `tiles.json`. Алиасы `wall/soil/road → *_0` сохраняют контракт спеки `atlas-generator` («атлас статики MUST содержать кадр `wall` как источник `tileSize`») — `parseAtlas` не меняется.
2. **Вход и выход атласа — только JPG.** Вход: только `.jpg` 130×130, прочие файлы игнорируются (PNG для тайлов больше нет нигде — см. `tiles-jpg`). Выход статики — `tiles.jpg` через `encodeJpg` (добавлен чейнжем `tiles-jpg` первой очередью); `tile-variants` использует готовый `encodeJpg` без изменений формата. Кандидаты генератора тоже JPG — тем же `encodeJpg`, конвертация при сборке не нужна.
3. **Хэш выбора варианта — целочисленный, без состояния:** `h = (x*374761393 + y*668265263 + seed*974634211) >>> 0; h ^= h >> 13; idx = h % count`. Пересчёт при каждом `drawCell` — чистый, хранить карту вариантов не нужно, `redrawTile` и ресайз стабильны автоматически. Альтернатива (предвычисленная карта вариантов в памяти) отвергнута: лишнее состояние и синхронизация при `soil → road`.
4. **`tileSeed` дефолт = FNV-1a/`xfnv` хэш строки `id`.** Решение Рэббита: seed выводится всегда, поле опционально. Хэш-функция seed живёт в `levels-loader.ts` рядом с парсингом, чистая и тестируемая.
5. **Генератор кандидатов — чистые пиксельные функции на `RgbaImage`.** `mulberry32(seed)` + value-noise через билинейную интерполяцию хэш-решётки (детерминирован, ~30 строк). Рецепты wall: `brick` (смещение рядов + тёмные швы), `stone` (крупные ячейки Вороного-лайт через jitter-grid + затенение границ), `grass` (зелёный шум + травинки-штрихи), `water` (синий шум + горизонтальные блики-синусоиды); `soil/earth`; `road/asphalt` (серый шум + светлые вкрапления, без разметки — тайл встаёт и вертикально). Выход — JPG через `encodeJpg` (добавлен чейнжем `tiles-jpg`) в `candidates/<type>/<recipe>-<seed>.jpg` + `candidates.json`.
6. **Галерея — один статический `tools/gallery.html` + `tools/serve.ts`?** Нет: галерея — только HTML+JS без сборки, открывается тем же `bunx serve .` (корень — репозиторий, `tools/` доступен по URL). Пути к манифестам задаются двумя `<input type=file>` + drag&drop ИЛИ fetch относительных путей по умолчанию (`../public/assets/candidates/candidates.json`, `../public/assets/sprites/tiles.json` + JPG рядом). Так галерея работает и из `tools/`, и скопированная куда угодно. Отдельного раннера не нужно — YAGNI.
7. **Миграции нет — только `level-001.json`.** Старых уровней сохранять нечего, тестовый уровень правится руками/генерируется заново. `raw/wall.jpg → raw/wall/0.jpg` и т.д. через `git mv`; отдельный legacy-путь в `gen-atlas.ts` не делаем — нет папок = fail-fast без записи.

## Risks / Trade-offs

- [Risk] 16 вариантов × 130px = 2080px ширина JPG — ок для Canvas 2D, вес `tiles.jpg` контролируем quality (дефолт 85 из `tiles-jpg`) → Mitigation: лимит мягкий, галерея показывает реальный размер файла.
- [Risk] JPG-кандидаты от генератора «стерильные» (чистый шум без художественности) → Mitigation: это затравка для отбора и ручной дорисовки; галерея принимает и ручные JPG-файлы.
- [Risk] `% count` при разных count на тип — хэш один, остатки разные, корреляция вариантов между типами незаметна → принято, визуально не значимо.

## Migration Plan

0. Сначала выполнить чейндж `tiles-jpg` (JPG-выход статики + `encodeJpg` в `atlas-codec.ts`).
1. `git mv` трёх JPG в папки как `0.jpg`, обновить `gen-atlas.ts` (папки + алиасы `wall|soil|road → *_0` для контракта `tileSize` в `parseAtlas`, JPG-выход), пересобрать `tiles.jpg/json`. Алиасы — не бэккомпат, а требование спеки `atlas-generator`.
2. Добавить `tileSeed` (опционально, дефолт-хэш от `id` покрывает `level-001.json` без правок) + `pickVariant` в рендер; `level-001.json` при желании дополнить явным seed.
3. Добавить `gen-tile-variants.ts` + `tools/gallery.html`.
