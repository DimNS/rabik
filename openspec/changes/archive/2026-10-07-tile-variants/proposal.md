## Why

Карта из трёх единственных спрайтов (`wall`, `soil`, `road`) выглядит плоско и повторяемо: глаз мгновенно считывает тайловую сетку. Нужна серьёзная вариативность (8–16 вариантов на тип) с детерминированным выбором по seed уровня, плюс отдельный генератор кандидатов и галерея для визуального отбора в `raw`-каталог.

## What Changes

- `raw`-каталог переходит на структуру по папкам: `raw/wall/*`, `raw/soil/*`, `raw/road/*` (только `.jpg` — PNG для тайлов больше нет, см. `tiles-jpg`); старые `wall.jpg/soil.jpg/road.jpg` мигрируют как `0.jpg` в свои папки.
- `gen-atlas.ts` собирает мульти-вариантный атлас: кадры `wall_0…wall_N`, `soil_*`, `road_*` в трёх рядах + алиасы `wall`/`soil`/`road` → `*_0` для обратной совместимости.
- Новый скрипт `scripts/gen-tile-variants.ts`: процедурный генератор кандидатов (seeded PRNG, рецепты: wall — кирпич/камень/трава/водная гладь; soil — земля с зерном; road — асфальт) в `candidates/<type>/<recipe>-<seed>.jpg` + `candidates.json`.
- Новая галерея в `tools/gallery.html` (вне `public`): просмотр кандидатов из `candidates.json` для отбора в `raw` + просмотр запечённых вариантов из собранного `tiles.json`.
- Рантайм: детерминированный выбор варианта `hash(x, y, tileSeed) % count`; `tileSeed` по умолчанию — хэш от `id` уровня. Логика `core/` не меняется, вариант — чисто визуальный слой.
- `LevelData` получает опциональное поле `tileSeed?: number`; валидация уровней его принимает, отсутствие означает дефолт от `id`.

## Capabilities

### New Capabilities

- `tile-variants`: генерация кандидатов-вариантов, галерея отбора, мульти-вариантный атлас и seeded-выбор варианта при отрисовке.

### Modified Capabilities

- `atlas-generator`: входы — папки вариантов вместо трёх фиксированных JPG; выходы — кадры `*_N` + алиасы вместо трёх кадров.
- `game-rendering`: отрисовка выбирает вариант кадра по типу клетки детерминированным хэшем координат и seed уровня, а не один кадр на тип.
- `level-loading`: уровень MAY содержать опциональное поле `tileSeed`; при отсутствии seed выводится из `id`.

## Impact

- Затронуты: `scripts/gen-atlas.ts`, `src/view/renderer.ts`, `src/view/sprite-atlas.ts` (проверка `wall` как источника `tileSize` — теперь через алиас/`wall_0`), `src/core/level-types.ts`, `src/data/levels-loader.ts`, `src/index.ts` (загрузка мульти-атласа).
- Новые: `scripts/gen-tile-variants.ts`, `tools/gallery.html`, `tools/`-раннер галереи.
- `core/game-rules.ts`, `core/game-state.ts`, `core/grid-utils.ts` — без изменений.
- Зависимости: ноль новых (генератор на существующем `atlas-codec.ts` + `node:zlib`).
- Порядок: выполняется ПОСЛЕ чейнжа `tiles-jpg` (первая очередь) — мульти-вариантный атлас сразу строится поверх JPG-выхода статики; загрузчик (`HTMLImageElement`) формат-агностичен, смены формата в `tile-variants` не требуется.
- Миграция ассетов: 3 JPG переезжают в папки; `tiles.png` удалён чейнжем `tiles-jpg`, `tiles.json` пересобирается поверх JPG-выхода.
