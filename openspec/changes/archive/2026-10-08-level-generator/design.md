## Context

См. `proposal.md` — зачем нужен генератор. Текущее состояние: правила ходьбы — `src/core/game-rules.ts` (`canMove` только на `soil`, асфальтирование входа, победа при нулевой `soil`), типы и инвентарь кадров — `src/core/level-types.ts`, валидация — `parseLevel` в `src/data/levels-loader.ts`, рендер — статичные кадры 130×130 без seed. Tools — статичные HTML (`tools/gallery.html`), скрипты — `scripts/gen-atlas.ts` на bun. Формат уровня менять нельзя, максимум поля 8×15.

## Goals / Non-Goals

**Goals:**
- Генерация от решения: уровень всегда выходит с известным маршрутом, солвер лишь подтверждает.
- Один детерминированный RNG на всё (размер + раскладка) — повтор по seed побайтово совпадает.
- Preview без внедрения: валидация + вердикт + прогон, ничего не пишет в игру.

**Non-Goals:**
- Редактор уровней, изменение формата/`parseLevel`/рендера/манифеста/прогресса.
- Новые зависимости в `package.json`, e2e с docker-образами.
- Умная эстетика стен сверх существующей таблицы масок `tile-mapping`.

## Decisions

**1. Генерация «сначала маршрут, потом стены».**
Случайное самонепересекающееся блуждание (self-avoiding walk) от старта по сетке ≤8×15 задаёт будущую `soil`; остальное — `wall` с долей по сложности. Альтернатива «насыпать случайно и фильтровать солвером» отвергнута: на плотных полях выход годных мал, генерация долго висит.

**2. Солвер — DFS с бэктрекингом на grid, переиспользуя правила.**
Проверка ходит только на `soil`-соседей, эмулируя `tryMove` без мутации `GameState` (копия grid + счётчик). Гамильтонов путь в общем NP-полон, но здесь старт известен и поле ≤120 клеток, а кандидат уже построен от маршрута — подтверждение быстрое; для чужих файлов — лимит попыток/времени с вердиктом `нерешаем`. Полный BFS отвергнут — больше памяти без выигрыша.

**3. RNG — `mulberry32`, seed строкой.**
Строковый seed хешируется в int32, один поток на размер и раскладку. Без seed — случайный из `crypto`. Альтернатива `Math.random` отвергнута: не детерминирован. Отдельных RNG на размер/раскладку нет — один поток проще и воспроизводимее.

**4. Сложность — лабиринтом, размеры жмутся к 8×15.**
Базы например `easy` ~7×12, `normal` ~8×13–14, `hard` 8×15, джиттер ±1 с обрезкой по максимуму. Параметры сложности: длина маршрута, доля стен, число тупиковых ответвлений. Размер один поле не усложняет — поэтому разброс маленький.

**5. Сначала `grid`, кадры — в конце детерминированно.**
Солвер и генератор работают на логических типах `wall`/`soil`/`road`; кадры назначаются после: `s101` база, `s102`/`s103` декор по хешу координат, `s301`/`s302` целыми горизонтальными парами, `w*` по 4/8-маске из `tile-mapping` (эталон — уровень `001`), старт `r101`, `s201`/`r102` только если люки решено включить. Генерировать сразу кадры — усложняет солвер и ломает пару `301/302`.

**6. Код — `src/gen/`, preview — `tools/level-preview.html` + скрипт.**
`src/gen/rng.ts`, `solver.ts`, `generator.ts` переиспользуют `level-types`/`levels-loader`/`game-rules`; тесты рядом (`bun test`). Preview повторяет паттерн `gallery.html`: открытие через `bunx serve`, загрузка `tiles.json`+уровня через fetch или file-input, рендер на canvas, прогон — подсветкой шагов. CLI/скрипт (`scripts/gen-level.ts`) для генерации в файл и `ai-check` тем же `make ai-check`. Изоляция: preview держит уровень в памяти, запись в `public/data/levels/` только явным экспортом.

## Risks / Trade-offs

- [Взрыв поиска на 8×15 для чужих карт] → лимит глубины/времени + эвристика (сначала ходы с меньшим числом выходов); генерация от маршрута почти не упирается в лимит.
- [Однообразие уровней одной сложности] → джиттер размера + разные старты + декор-варианты; seed даёт разнообразие без потери воспроизводимости.
- [Нестыки стен при автокадрах] → строго таблица масок + сверка с эталоном `001` в тестах.
- [Соблазн расширить формат (`tileSeed` в JSON)] → запрещено `level-loading`: seed живёт только в генераторе/preview, в файл не пишется.

## Migration Plan

Чисто аддитивное изменение: новые файлы в `src/gen/`, `tools/`, `scripts/`; существующие уровни, манифест и игра не трогаются. Откат — удалить новые файлы. Отдельного деплоя нет.
