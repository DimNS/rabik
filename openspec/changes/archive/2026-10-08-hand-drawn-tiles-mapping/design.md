## Context

Сейчас уровень — сетка типов `wall`/`soil`/`road`, кадр выбирается хэшем `hash(x, y, tileSeed) % count` (стены — кластером 2×2), атлас собирается с индексными именами `wall_0…`, seed выводится из `id`. В `public/assets/raw/` лежат 55 ручных кадров (wall ×47, soil ×6, road ×2) — см. инвентарь ниже; эталон раскладки — уровень `001` 7×7 из описания change. Обратной совместимости нет (см. proposal.md). Правила игры не меняются: тип клетки выводится из префикса кадра.

Инвентарь по факту просмотра: soil — `101` голая земля, `102` камни, `103` камни и лужа, `201` люк на земле, `301`+`302` левая/правая половины куска дороги; road — `101` асфальт, `102` люк на асфальте; wall — `101` куст-внутренность, `201` изолированная трава с каймой, `3xx` кромки/углы, `40x` внешние углы, `405–415` внутренние углы, `501–516` вторые варианты кромок, двойные кромки и кадры с объектами (барьеры `302`, знаки `312`/`506`, куст на кромке `504`).

## Goals / Non-Goals

**Goals:**
- Один слой кадров в уровне, типы выводятся из префикса; статичная отрисовка без seed и хэшей.
- Именованный атлас (`w307`, `s101`, …), переход люка `s201 → r102`, мигрированный уровень `001`, галерея под raw.
- Таблица «маска → кадр», достаточная для ручной раскладки и будущего генератора.

**Non-Goals:**
- Сам генератор уровней (этот change даёт только таблицу-эталон; генератор — отдельный change).
- Изменение правил игры, кролика, layout/canvas, формата `rabbit.json`.

## Decisions

### 1. Модель уровня: один слой кадров, типы — производные

`tiles` в JSON — `string[][]` вида `w403`/`s301`/`r101`; валидация — regex `^[wsr]\d+$` плюс принадлежность инвентарю. `parseLevel` строит оба представления: `frames: string[][]` (источник отрисовки) и `grid: CellType[][]` (префикс → тип, источник правил). `tileSeed` запрещён (поле в JSON → ошибка), `hashLevelId` удаляется. Альтернатива «два слоя (типы + кадры)» отклонена: один источник правды, меньше рассинхрона; типы и так выводятся однозначно.

### 2. Атлас: те же три ряда, имена из файлов

Раскладка `tiles.jpg` не меняется (ряд на тип, ширина — по самому полному ряду, 47 кадров wall): меняется только ключ кадра — `<буква типа><имя файла без расширения>` (`307.jpg` в `wall/` → `w307`). Индексных имён и алиасов (`wall_0`, `wall`) нет. `tileSize` берётся из любого кадра (все 130×130). `gen-atlas.ts` правится точечно: имя кадра из имени файла + та же валидация 130×130. Разделение `tiles`/`rabbit`, JPG для статики и прозрачность кролика — без изменений.

### 3. Состояние и рендер: кадры рядом с типами, одна динамика — люк

`GameState` получает `frames: string[][]` рядом с `grid`; `createGameState` копирует оба из уровня. Ход в `game-rules.ts` обновляет оба синхронно: обычный шаг на `soil` → тип `road` + кадр `r101`; шаг на `s201` → тип `road` + кадр `r102`. `renderer.drawCell` берёт имя кадра из `state.frames`, `redrawTile` перерисовывает только changed-клетку как раньше. `pickVariant`/`pickWallVariant`/`variantFrame`, `tileSeed` в `RendererOptions` и их тесты удаляются; тесты — на прямой выбор кадра и переход люка.

### 4. Таблица маппинга soil/road (полная)

- Обычная земля: `s101` базовый; `s102`/`s103` — варианты разнообразия только на клетках обычной земли (не люк, не пара), распределение фиксируется в данных уровня, на логику не влияет.
- Люк: `s201` — клетка-люк (soil для счётчика и ходьбы); несколько люков на уровень разрешены, переходят независимо.
- Пара: `s301` строго слева от `s302`, только горизонтально, неделимый блок 2×1 (генератор в будущем ставит блоком, валидатор проверяет парность).
- Асфальт: `r101` базовый; `r102` — через переход из `s201` или изначально в данных уровня.

### 5. Таблица маппинга wall (маска → кадры)

Маска: 4 соседа `N`/`E`/`S`/`W`, бит = 1 если сосед `wall`; край карты считается `wall`. Серая кайма на кадре смотрит в открытую сторону; у внешних углов скругление смотрит в сторону массива стен.

| Маска (N E S W) | Группа | Кадры |
|---|---|---|
| 1111 (+диагонали тоже wall) | Внутренность | `w101` |
| 0000 | Изолированная | `w201`; варианты разнообразия той же маски: `w312` (знак), `w506` (знак «стоп») |
| 1110 / 1101 / 1011 / 0111 (одна открытая сторона) | Кромка | Открыта S → `w307`, `w311`, `w512`, `w516`, `w504` (куст); открыта N → `w310`, `w502`, `w514`, `w507`, `w302` (барьеры лицом в открытую сторону); открыта E → `w305`, `w303`, `w515`; открыта W → `w304`, `w306`, `w313`, `w509`, `w511`, `w501` (с внутренним углом SE) |
| Ровно две смежные wall (угол массива) | Внешний угол | Скруглённые: wall S+E → `w403`; S+W → `w404`; N+E → `w402`; N+W → `w401`. Полосные того же профиля: wall S+E → `w301`, `w508`; wall S+W → `w314`; wall N+W → `w513` |
| Только одна смежная wall (тупик) | Тупик | wall E → `w309`; остальные ориентации → фолбэк `w201` |
| 1111, но открыта диагональ | Внутренний угол | Серия `405–415` по открытым диагоналям (один кадр на каждую комбинацию; точную раскладку серий сверить визуально при реализации — см. Risks) |
| Две противоположные открыты (коридор 1×N) | Двойная кромка | `w308`, `w503`, `w505`, `w510`, `w513` — по совпадению профилей кромок с соседями |
| Тупик (одна wall / прочие редкие) | Фолбэк | `w201`; генератор таких конфигураций избегает, авторская расстановка — по вкусу |

Несколько кадров на одну маску — варианты профиля кромки (неровный край по углам/сторонам): выбирается тот, чей профиль продолжает профиль соседа по общей границе (принцип Ван-тайлов: стык обязан совпадать). Граничные линии карты шьются uniform-кадром по всей линии ради непрерывности профиля, но ТОЛЬКО для клеток с открытой стороной: клетка с замкнутыми 4 сторонами и открытыми диагоналями всегда получает внутренний угол (`(0,2)` в `001` — `w406`, а не `w305` из uniform-столбца). Кадры с объектами участвуют в этом выборе наравне с пустыми. Проверенные соответствия внутренних углов: NE+SE → `w406`, NW → `w405`, SW → `w407`, NW+SW → `w408`; остальные комбинации серии `405–415` — по тем же выемкам, сверить в галерее при генераторе. Замер по золотому `001`: медианный перепад однотипных стыков 2.3, пара `s301↔s302` — 11.2 (кусок дороги непрерывен); единственный высокий стык `w305↔w310` (73.8) — авторский уступ кромки на стыке uniform-столбца, не дефект.

### 6. Аудит кромок инструментами

`tools/gallery.html` переводится на вкладки raw/именованный атлас (см. спеки `tile-variants`); `tools/seams.html` используется для проверки непрерывности профилей: собирается тестовый уровень со всеми парами соседства из таблицы, шов считается пройденным визуально. Автопиксельного сравнения нет — кромка неровная по дизайну, эталон — глаз.

### 7. Удаления

`scripts/gen-tile-variants.ts` + тесты, каталог `candidates/`, вкладка кандидатов в галерее, `tileSeed`/`hashLevelId`, `pickVariant`/`pickWallVariant`/`variantFrame`, цель `candidates` в Makefile. Поле `tileSeed` в старых JSON после миграции отсутствует (уровень один — `001`).

## Risks / Trade-offs

- [Risk] Толкование кромок 5xx/405–415 по миниатюрам может ошибаться → Mitigation: при реализации сверить каждый кадр серии с соседями в галерее, таблицу поправить; спеки при этом не меняются (они ссылаются на design).
- [Risk] JPG-артефакты на стыке двух кадров с разным профилем → Mitigation: правило профилей (§5) + шов-аудит; атлас тот же кодек, новых искажений нет.
- [Risk] Пара `s301`/`s302` разорвётся будущим генератором → Mitigation: валидатор уже требует парность (спека `tile-mapping`), генератор ставит неделимым блоком.
- [Trade-off] Фолбэк `w201` для редких масок вместо dedicated-кадров: простота сейчас, идеальная картинка — когда генератор научится избегать таких мест.

## Migration Plan

1. Код: `level-types` (тип кадра, `frames`), `levels-loader` (валидация, запрет seed/старых типов), `game-rules` (двойное обновление + люк), `renderer` (прямые кадры, удалить pick*), тесты.
2. `gen-atlas.ts` → именованные кадры; пересобрать `tiles.json`/`tiles.jpg`; `make atlas`.
3. Уровень `001` → эталонная раскладка из описания change (золотые кадры дословно); `start` без изменений (кадр `r101`).
4. Галерея → вкладки raw/атлас; удалить `gen-tile-variants`, `candidates/`, цель `candidates`.
5. Проверка: `make ai-check`, визуальный прогон `001` + шов-аудит.
6. Откат: revert коммита; старый формат отклоняется новым загрузчиком, флага совместимости нет (решение пользователя).
