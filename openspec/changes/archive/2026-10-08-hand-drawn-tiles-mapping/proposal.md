## Why

Процедурные JPG-варианты выглядят чужеродно, а в `raw/` уже лежат вручную нарисованные тайлы (wall ×47, soil ×6, road ×2), заточенные под красивую карту с автотайлингом по окрестности. Без формализованной инструкции маппинга и формата уровня будущая автоматическая генерация уровней расставит их неправильно (швы, оборванные дороги, неверные люки и пары).

## What Changes

- Инвентаризация всех кадров в `public/assets/raw/` (wall/101…516, soil/101…302, road/101…102) и формальная инструкция маппинга «тип + окрестность → конкретный кадр» для будущей автогенерации.
- Формат уровня: только явные кадры (`w403`, `s301`, …); логический тип (`wall`/`soil`/`road`) выводится из префикса кадра. Старый формат (сетка типов) не поддерживается, уровень `001` мигрируется.
- Отрисовка по явным кадрам вместо `hash(x, y, seed) % count`; динамическое правило `soil/201 → road/102` при проходе кролика (открытый/закрытый люк).
- Сборка атласа по именам файлов (`s101`, `w307`, …), а не по индексам `wall_0…`; алиасы типов сохраняются как fallback.
- Особые правила: пара `soil/301 + soil/302` только горизонтально и только в этом порядке; `wall/101` — внутренность массива wall; `wall/201` — изолированная стена среди soil/road.
- **BREAKING**: процедурный генератор вариантов (`tile-variants`) и хэш-кластеризация стен (`wall-coherence`, блок 2×2) заменяются детерминированным автотайлингом по окрестности.

## Capabilities

### New Capabilities
- `tile-mapping`: инструкция маппинга ручных тайлов — какой кадр ставится по типу клетки и её 4/8-окрестности, особые пары и переходы состояний; эталон для ручной раскладки и будущей автогенерации уровней.

### Modified Capabilities
- `level-loading`: формат уровня только из явных кадров без обратной совместимости со старым форматом.
- `game-rendering`: отрисовка по явным кадрам уровня + пересчёт соседей и переход `soil/201 → road/102` при асфальтировании.
- `atlas-generator`: именованные кадры из `raw/` с сохранением номеров файлов вместо `*_0…N`.
- `wall-coherence`: замена кластеризации 2×2 на автотайлинг по окрестности (внутренность/кромка/угол).
- `tile-variants`: вывод из эксплуатации процедурной генерации кандидатов в пользу ручных тайлов из `raw/`.

## Impact

- Затронуты: `scripts/gen-atlas.ts` (именованные кадры), `src/view/renderer.ts` (`variantFrame`/`pickVariant`/`pickWallVariant`), `src/data/levels-loader.ts` + `src/core/level-types.ts` (формат уровня, валидация), `public/data/levels/*` (пример `001` 7×7), `public/assets/sprites/tiles.json`.
- Правила игры (`game-rules`: проходимость, счётчик `soil`, победа) не меняются — тип клетки выводится из префикса кадра.
