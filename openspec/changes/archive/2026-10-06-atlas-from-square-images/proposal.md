## Why

Текущий `scripts/gen-atlas.ts` не умеет использовать готовую графику — он заливает кадры сплошными цветами по `atlas.json`. У пользователя уже есть JPG-плитки 130×130 и PNG-стрип кролика 1170×130 с прозрачным фоном (9 кадров), но собрать из них рабочий атлас для игры нечем.

## What Changes

- `scripts/gen-atlas.ts` собирает атлас из готовых JPG-плиток 130×130 вместо заливки цветами.
- Поддержка нарезки горизонтального PNG-стрипа кролика 1170×130 с прозрачным фоном на 9 кадров 130×130 с сохранением альфы.
- Раздельная сборка двух атласов: статичные плитки (`wall` / `soil` / `road`) и кадры анимации кролика (`rabbit_0` … `rabbit_8`).
- Генерация `atlas.json` + `atlas.png` в формате, который уже понимает `loadAtlas` / `parseAtlas` (frames + meta + duration для анимации).
- Исходники лежат отдельно от результата: входные JPG/PNG не затираются выходными атласами.

## Capabilities

### New Capabilities
- `atlas-generator`: сборка PNG-атласов и `atlas.json` из JPG-плиток 130×130 и PNG-стрипа анимации с альфой, включая раздельные атласы статики и анимации.

### Modified Capabilities
- Нет.

## Impact

- `scripts/gen-atlas.ts` — основной файл изменений (декодирование JPG/PNG, компоновка, кодирование PNG с альфой для кролика, генерация JSON).
- `public/assets/sprites/` — выходные `tiles.*` + `rabbit.*`; входные исходники JPG/PNG.
- `src/view/sprite-atlas.ts` — без изменений логики, но формат выхода обязан оставаться совместимым с `parseAtlas` (поле `wall` как источник `tileSize`).
- Зависимости: только dev-окружение (Bun/Node + dev-only JPEG-декодер для скрипта), 0 runtime-зависимостей игры не меняется.
