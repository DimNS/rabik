## Context

См. `proposal.md` (Why) — текущий `scripts/gen-atlas.ts` заливает кадры цветами и не читает PNG. Ограничения, формирующие подход: игра — 0 runtime-зависимостей, атлас потребляется через `parseAtlas` / `loadAtlas` в `src/view/sprite-atlas.ts` (поле `wall` — источник `tileSize`), а `src/view/renderer.ts` сегодня берёт и плитки, и кадры кролика из одного `SpriteAtlas`. Спека — `specs/atlas-generator/spec.md`.

## Goals / Non-Goals

**Goals:**
- Собрать два рабочих атласа из готовой графики: статика из JPG 3×130 и анимация из PNG-стрипа 9×130 с сохранением альфы; рантайм игры остаётся с 0 зависимостями (единственная новая зависимость — dev-only декодер JPEG для скрипта).
- Выход, который `parseAtlas` принимает без правок формата.

**Non-Goals:**
- Ресайз/масштабирование исходников, упаковщик произвольных размеров, оптимизация веса PNG.
- Поддержка exotic PNG (interlace, палитра, gray, 16 бит) — только то, что отдают обычные экспортеры.
- Правки геймплея, уровней, аниматора.

## Decisions

1. **Раскладка файлов: входы отдельно от выходов.** Входы — `public/assets/raw/wall.jpg`, `soil.jpg`, `road.jpg` (130×130) и `rabbit-strip.png` (1170×130 с альфой); выходы — `public/assets/sprites/tiles.{png,json}` и `rabbit.{png,json}`. Плюс флаги `--raw-dir`, `--out-dir`, `--frame-duration`. Альтернатива «всё в одной папке» отвергнута: генератор затёр бы исходники и loader начал бы подхватывать лишний мусор.
2. **Декодеры: PNG вручную, JPEG — одна pure-JS dev-зависимость.** PNG-декодер — `IHDR`/`IDAT`/`IEND` через `node:zlib` `inflateSync` + снятие фильтров (None/Sub/Up/Average/Paeth), поддержка 8-бит truecolor (type 2) и truecolor+alpha (type 6) без interlace; JPEG-декодер — `jpeg-js` (только для скрипта, в рантайм игры не попадает). Кодировщик — расширение существующего `encodePng`: `tiles.png` пишется как RGB (color type 2), `rabbit.png` — как RGBA (color type 6) с попиксельной альфой стрипа. Альтернативы: ручной JPEG-декодер — отвергнут (сотни строк ради dev-утилиты); системные `convert`/`ffmpeg` — отвергнуты (их нет в окружении); `pngjs` — отвергнут (лишняя зависимость ради dev-утилиты, принцип минимума); декод через браузерный Canvas — отвергнут (скрипт должен работать headless под `bun`).
3. **Компоновка — одна строка, фиксированный порядок.** `tiles.png` — `wall|soil|road` → 390×130; `rabbit.png` — 9 кадров стрипа как есть → 1170×130 (послойное копирование строк слева направо). Альтернатива универсальному shelf-packing отвергнута — YAGNI для известного набора 3+9 кадров.
4. **Fail-fast валидация входов.** Проверяем размеры до записи: плитки строго 130×130, стрип строго 1170×130, иначе — ошибка в stderr, ненулевой exit, ни один выходной файл не пишется (атомарность прогона). Частичная запись запрещена, чтобы не оставить игру с рассинхроном PNG/JSON.
5. **Два атласа → точечная правка потребления.** `tiles.json` содержит `wall` (от него `tileSize` = 130); `rabbit.json` — `rabbit_0`…`rabbit_8` с `duration` (дефолт 120 мс). `renderer.ts` сегодня берёт всё из одного атласа, поэтому bootstrap/`RendererOptions` получают два `SpriteAtlas` (`tiles` для `drawCell`, `rabbit` для `animator.current()`); `tileSize` берётся из tiles-атласа. Альтернатива «один комбинированный атлас» остаётся доступной как флаг `--combined atlas.{png,json}` для совместимости, но по умолчанию — два раздельных набора по спеке.

## Risks / Trade-offs

- [Risk] Исходник сохранён в палитре/gray/interlace → декодер его не возьмёт → Mitigation: явная ошибка «пересохраните как 8-bit RGB/RGBA без interlace».
- [Risk] JPEG-артефакты на стыках пикселей после копирования в атлас → Mitigation: пиксели переносятся как есть, без ресайза и повторного сжатия до сборки атласа; визуально бьётся только качеством исходника.
- [Risk] `rabbit.json` без кадра `wall` не проходит `parseAtlas` как самостоятельный атлас → Mitigation: `tileSize` всегда из `tiles`; rabbit-атлас грузится тем же `parseAtlas`, но `wall` в него не подмешиваем — валидируем кадры по границам PNG напрямую.
- [Risk] Молчаливая подмена длительности анимации → Mitigation: единый `--frame-duration` на все 9 кадров, значение пишется в каждый `duration`.
- Trade-off: ручной PNG-код длиннее, чем `pngjs` в одну строку, но сохраняет 0 зависимостей и переиспользует уже лежащие в скрипте `chunk`/`crc32`.

## Migration Plan

1. Положить исходники в `public/assets/raw/`, прогнать `bun scripts/gen-atlas.ts`, проверить `make ai-check` и загрузку обоих JSON через `parseAtlas`.
2. Обновить bootstrap на загрузку `tiles.json` + `rabbit.json`, удалить старый `atlas.{png,json}`.
3. Rollback: восстановить старые `atlas.{png,json}` и bootstrap из git — формат loader'а не менялся.
