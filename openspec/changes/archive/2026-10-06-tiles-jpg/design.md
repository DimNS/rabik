## Context

См. `proposal.md` (Why). `gen-atlas.ts` сейчас кодирует статику через `encodePng(..., withAlpha=false)`; декодер JPG (`decodeJpg` на `jpeg-js`) уже есть. Энкодер `jpeg-js` (`lib/encoder.js`) доступен в той же зависимости без новых пакетов.

## Goals / Non-Goals

- Goals: `tiles.jpg` + `tiles.json` с `meta.image="tiles.jpg"`; удаление `tiles.png`; игра грузится без правок `src/`.
- Non-Goals: смена качества/рецептов плиток; трогание `rabbit.png`; мульти-вариантность (это `tile-variants` поверх).

## Decisions

1. **Энкодер — `jpeg-js.encode` с quality 85.** Уже в devDeps (`~0.4.4`), ноль новых пакетов (проверено: `node_modules/jpeg-js/lib/encoder.js` на месте). Quality 85 — баланс вес/артефакты для плоских 130px-тайлов; параметр — константой с флагом `--jpg-quality` для подбора глазами. Альтернатива (писать свой JPEG-энкодер) отвергнута — сотни строк DCT/Huffman ради существующей зависимости.
2. **Прокси `encodeJpg` в `atlas-codec.ts`** рядом с `encodePng`, чтобы весь кодек жил в одном модуле; `gen-atlas.ts` только переключает вызов и имя файла.
3. **Fail-fast сохраняется:** сначала сборка обоих выходов в памяти, запись — только после успеха; при ошибке кодирования ни один файл не перезаписывается.
4. **Удаление `tiles.png` — частью задачи сборки**, не руками: генератор чистит устаревший `tiles.png` при успешной записи `tiles.jpg`, чтобы репозиторий не хранил оба.

## Risks / Trade-offs

- [Risk] JPG-артефакты на резких границах (кирпичные швы) при quality 85 → Mitigation: флаг `--jpg-quality`, подбор глазами в галерее; дефолт 85, поднять до 90 если глаз заметит.
- [Risk] Старые ссылки на `tiles.png` (кеш, `dist/`) → Mitigation: `meta.image` — единый источник имени для загрузчика; `dist/` пересобирается.

## Migration Plan

1. Добавить `encodeJpg` в `atlas-codec.ts`.
2. Переключить `gen-atlas.ts` на JPG-выход статики (+ флаг quality).
3. Пересобрать, удалить `tiles.png`, проверить загрузку игры без правок `src/`.
4. Откат: `git revert` + пересборка.
