## Context

См. `proposal.md` (Why). Текущее состояние: `Difficulty = 'easy' | 'normal' | 'hard'` в `src/gen/generator.ts` и `src/core/level-types.ts`; пресеты `DIFFICULTY_PRESETS` с базой и `cover`; размер = база + джиттер ±1 с клэмпом `MAX_WIDTH`/`MAX_HEIGHT`; `cropWalls` режет пустые поля до bbox+1. Валидация `difficulty` строковым сравнением в `levels-loader.ts`, `gen-level.ts`, `level-preview.ts`. Цвета кружков в `DIFFICULTY_COLORS` (`src/view/ui.ts`).

## Goals / Non-Goals

**Goals:**
- `nightmare` всегда 8×15 и визуально запутанный (ветвления, без длинных прямых).
- Сохранить детерминизм по seed и гарантию проходимости через `solveLevel`.

**Non-Goals:**
- Не менять баланс `easy`/`normal`/`hard`, не перегенерировать существующие уровни в `index.json`.
- Не вводить новые ассеты иконок — только цветной `div`-кружок.

## Decisions

- **Пресет `nightmare: { w: 8, h: 15, cover: 0.6 }` + пропуск джиттера и кропа.** Размер фиксируется до `findWalk`, `cropWalls` для nightmare не применяется (или применяется только если не уменьшает размер). `cover` 0.6 (как `hard`): замер показал, что 0.65+ даёт ~19% сидов, которые `solveLevel` не решает за лимит (78 клеток), а 0.6 — 60/60 за <300мс; сложность держится фикс-максимумом и фильтром поворотов. Альтернатива «оставить кроп» — отклонена: кроп срезал бы поле ниже 8×15 на редких сидах, нарушая требование «всегда MAX».
- **Запрет простых коридоров через пост-фильтр кандидата, а не через новый алгоритм walk.** После построения `grid` считаем максимальную длину прямого отрезка маршрута решения и число поворотов/ветвлений; кандидат с отрезком длиннее порога (например >5 клеток без поворота) или без ветвлений отбрасывается, цикл `attempt` повторяется (лимит попыток поднять с 10 до ~30 для nightmare). Альтернатива «переписать findWalk с bias к поворотам» — отклонена: сложнее, ломает детерминизм остальных сложностей; фильтр — минимальный дифф в общей функции генерации.
- **Расширение union-типа одной строкой везде + общий хелпер `isDifficulty`.** `Difficulty` включает `'nightmare'`; проверки `!== 'easy' && ...` заменяются на проверку через массив/сет. Альтернатива «оставить строки как есть» — отклонена: легко забыть одно место.
- **Фиолетовый кружок `#a855f7` одной записью в `DIFFICULTY_COLORS`.** Чёрный `#000000` отклонён: не виден на тёмном фоне экрана выбора (`#111`). Без изменений разметки. Альтернатива отдельному PNG — отклонена ранее по той же причине.

## Risks / Trade-offs

- [Риск] Пост-фильтр коридоров может отбрасывать много кандидатов → медленная генерация на nightmare → Митигация: поднять лимит попыток только для nightmare, порог длины отрезка подобрать (5–6), замерить время (<2с как в существующем тесте).
- [Риск] Фикс 8×15 + высокий `cover` даёт долгие решения солвером → Митигация: `cover` 0.6 (замер: 0.65+ ломает `solveLevel` на ~19% сидов); тест на время генерации.
- [Риск] Забытые `.js`-артефакты рядом с `.ts` (`tools/level-preview.js`, `src/gen/*.js`) → Митигация: проверить, коммитятся ли они; если да — обновить или перегенерировать, иначе только `.ts`.

## Migration Plan

- Прямая замена кода, отката — revert коммита. Существующие `index.json` и уровни не трогаются; новые nightmare-уровни добавляются отдельно после реализации.
