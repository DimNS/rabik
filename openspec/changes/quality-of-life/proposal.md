## Why

Игра теряет качество и читаемость на больших экранах (тайл растягивается без предела), кролик не показывает направление движения, нет сигнала о проигрыше при замуровывании себя асфальтом, а у проекта нет README для входа новых разработчиков.

## What Changes

- Ограничить максимальный размер тайла 130×130 px (исходный размер спрайтов), чтобы на больших экранах графика оставалась резкой.
- Задать ориентацию спрайта кролика по умолчанию «вверх»; при каждом успешном шаге поворачивать спрайт в сторону шага (`up` / `down` / `left` / `right`).
- Добавить определение «game over»: после успешного шага, если вокруг кролика нет ни одной соседней клетки `soil` куда можно пойти (и уровень при этом не решён), писать сообщение в лог по аналогии с «win».
- Добавить `README.md` с описанием проекта: что это, как запустить, структура, спрайты/уровни, правила игры.

## Capabilities

### New Capabilities

- Нет новых capabilities: все поведенческие изменения укладываются в существующие `game-rendering` и `game-rules`; README — чистая документация без spec-поведения.

### Modified Capabilities

- `game-rendering`: предел размера тайла 130px и поворот спрайта игрока по направлению последнего шага (дефолт — вверх).
- `game-rules`: условие «game over» (тупик без доступной `soil` после шага) с фиксацией в состоянии/логом по аналогии с победой.

## Impact

- `src/view/layout.ts` (`computeLayout` — cap `tileSize` на 130).
- `src/view/renderer.ts` + `src/view/sprite-anim.ts` / `src/index.ts` (хранение направления кролика, поворот при отрисовке, дефолт `up`).
- `src/core/game-rules.ts` + `src/core/game-state.ts` + игровой цикл в `src/index.ts` (проверка соседних `soil` после шага, флаг/лог `game over` без конфликта с `solved`).
- Тесты: `layout.test.ts`, `renderer.test.ts`, `game.test.ts` / `game-rules`.
- Новый файл `README.md` в корне (документация, без влияния на рантайм).
