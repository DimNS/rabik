## Purpose

Возможность устанавливать игру OneWay на главный экран мобильного устройства и запускать её офлайн как нативное приложение в standalone-режиме.

## Requirements

### Requirement: Web App Manifest доступен и валиден

Система SHALL отдавать валидный Web App Manifest по пути `manifest.webmanifest`, связанный из `index.html` через `<link rel="manifest">`. Манифест SHALL содержать имя приложения, `start_url`, `display: standalone`, `theme_color`, `background_color` и иконки 192px и 512px (включая maskable).

#### Scenario: Браузер находит манифест

- **WHEN** пользователь открывает `index.html`
- **THEN** в документе есть `<link rel="manifest" href="manifest.webmanifest">` и файл манифеста загружается с HTTP 200 и валидным JSON

#### Scenario: Манифест проходит installability-критерии

- **WHEN** браузер проверяет критерии установки (Chrome Lighthouse PWA / Android install prompt)
- **THEN** имя, иконки 192/512, `start_url` и `display: standalone` распознаны и установка предложена

### Requirement: Запуск в standalone-режиме с иконкой

Система SHALL предоставлять иконки приложения (192px, 512px, `apple-touch-icon` 180px) так, чтобы добавленная на главный экран игра запускалась без браузерного chrome, с `theme_color` и полноэкранным canvas.

#### Scenario: Добавление на главный экран

- **WHEN** пользователь выбирает «Добавить на главный экран» на Android/iOS
- **THEN** на экране появляется иконка OneWay, запуск открывает игру в standalone/fullscreen без адресной строки

### Requirement: Офлайн-доступ после первого визита

Система SHALL регистрировать Service Worker (`sw.js`), который при первом онлайн-визите кэширует оболочку (HTML, JS, манифест, иконки, спрайты, данные уровней), а при последующих запусках без сети SHALL отдавать игру из кэша.

#### Scenario: Повторный запуск без сети

- **WHEN** пользователь один раз открыл игру онлайн, затем отключил сеть и перезапустил
- **THEN** игра загружается из кэша и доходит до стартового экрана без ошибок сети

#### Scenario: Отсутствует выдача битого состояния

- **WHEN** часть кэшируемых ассетов отсутствует в кэше при офлайне
- **THEN** пользователь видит стартовую оболочку (index), а не пустую страницу

### Requirement: Обновление кэша при новой версии

Система SHALL версионировать кэш Service Worker так, чтобы новая сборка заменяла старый кэш и активировалась без зависания на старой версии и без ручной очистки.

#### Scenario: Деплой новой версии

- **WHEN** вышла новая сборка с другим номером версии кэша
- **THEN** Service Worker устанавливает новый кэш, удаляет старый и после перезагрузки отдаёт новые файлы
